# P06.19 — US-019 Load a Score from an `.abc` File (Story Increment)

**Version:** 1.0
**Mode:** Story increment (`P06_implementation.md` v2.0, section 2.2)
**Story:** US-019 / HU19 · P1 · 2 SP · MVP Supporting (CR-002)
**Contributor:** frontend — TEAM-001 session (`pipeline/mvp2-p00-context`)

## 1. What to implement

A user on "Crear partitura" can choose an `.abc` file from their device; its text appears in the content field with its line breaks, the format becomes ABC, and the text stays editable before publication. The file is read in the browser and never uploaded or stored.

## 3. Scope

- File picker restricted to `.abc`; validation of extension (M-08a), empty file (M-08b), UTF-8 readability (M-08c), 1,000 characters (M-08d); BOM and CRLF normalized.
- Confirmation before replacing existing content (SCR-010); cancel keeps the content.
- On success: content inserted, ABC selected, message M-14.
- Publication uses the existing MVP 1 validation.

**Out of scope / constraints:**
- Edit page: the delivered HU05 edit page does not edit content (record as a finding).
- No upload endpoint, no file storage.

## 4. Required verification

- `tsc --noEmit`, `vite build`.
- Browser: invalid extension rejected; valid file (CRLF) inserted with line breaks; ABC selected; publish succeeds with loaded content; 375 px layout.
