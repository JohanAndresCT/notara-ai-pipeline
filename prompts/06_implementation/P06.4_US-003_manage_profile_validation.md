## 5. Detailed Validation

### 5.1 Authentication and authorization

- Verify unauthenticated profile read/update, password change, and photo fetch
  are denied.
- Verify all mutations use CSRF-protected unsafe methods.
- Verify the current user is taken from the session; no client-supplied user ID
  can alter another account.

### 5.2 Profile persistence

- Read profile data for a registered test user and check safe fields only.
- Update name and instrument; verify response and a fresh GET show persisted
  values.
- Submit invalid name/instrument and verify no partial updates.
- Confirm email and password hashes are not editable/returned through profile
  APIs.

### 5.3 Photo validation/storage/privacy

- Accept valid JPEG/JPG and PNG image content with matching supported suffix.
- Reject unsupported suffixes, mismatched or malformed bytes, over-limit
  uploads, and unauthenticated uploads with clear errors and no profile change.
- Verify a failed replacement retains the old photo.
- Verify a successful replacement persists, is retrievable only through the
  intended authenticated path, and removes the superseded stored file if that
  is the implementation policy.
- Verify file bytes live in configured Django storage and only their path is
  persisted in the database.
- Record the configured size cap and mark it as a technical assumption pending
  Product Owner confirmation if not separately approved.

### 5.4 Password change

- Verify valid password change uses Django hashing and preserves the current
  authenticated session.
- Verify invalid current password and missing/invalid new password do not
  change the stored password.
- Confirm password values/hashes are not returned or logged.

### 5.5 Frontend and responsive behavior

- Verify profile fields, photo preview, save/loading/error states, and password
  form work with real API responses.
- Verify profile state refreshes immediately after a successful save.
- Record browser/version/viewport for each check; target Chrome, Edge, and
  Firefox at 360, 768, and 1280 px as available. Do not claim untested cells.
- Check no overflow or obscured profile controls at mobile and desktop widths.

## 6. Source Alignment Review

## 8. Result Rules

- **PASS:** all requested and canonical relevant criteria pass; image content,
  persistence, authentication, and password-change behavior are verified; no
  material findings remain.
- **PASS_WITH_WARNINGS:** core behavior passes with non-blocking browser,
  storage, upstream-scope, or Product Owner review gates.
- **FAIL:** implementation exists but a material criterion, data-integrity, or
  security check fails.
- **BLOCKED:** implementation is absent or a concrete prerequisite prevents
  reliable validation.

Severity: CRITICAL (auth/data exposure or unsafe file handling), HIGH
(profile/photo/password integrity failure), MEDIUM (material scope/security,
accessibility, or verification gap), LOW (minor documentation/maintainability).
Never claim Product Owner approval or unexecuted browser/storage checks.
